# MuyuClash Legacy
## 完整产品设计、技术架构与一次性交付开发规范

**文档版本：V3.0 Final Design Candidate**  
**目标平台：iOS 6.0+ / ARMv7 / 已越狱设备**  
**开发原则：兼容性优先、完全本机、完整交付、精简测试**

# 第一章：项目定位

## 1.1 产品目标

MuyuClash Legacy 是一款针对旧版 iOS 设计的 Clash/Mihomo 兼容代理客户端。

它需要在 iOS 6 设备上独立完成代理连接、规则分流、DNS 解析、节点管理、配置订阅及系统流量接管。

产品不是远程 Mihomo 控制器，也不是简单的 SOCKS5 开关或网页客户端。

**最终目标：让旧版 iOS 设备尽可能获得现代 Clash 客户端的完整功能和操作体验。**

## 1.2 一次性交付原则

本项目不采用「先发布基础版，以后再补核心功能」的公开交付方式。

首次正式发布必须提供：

- 完整原生 UI 和所有约定页面。
- 可正常运行的本地代理核心。
- 已约定的主要现代代理协议。
- Clash YAML 配置解析、策略组和规则引擎。
- 订阅导入、更新和配置管理。
- DNS 与系统流量接管。
- 后台运行和自动恢复。
- 连接日志、诊断和配置检查。
- 可直接安装的 `.deb` 包。
- 完整源码、构建说明及依赖许可证文件。

开发内部允许按模块分工、并行实现和修复问题，但最终只交付一个集成完毕的正式版本。

不可将演示界面、空接口、Mock 数据、尚未实现的协议或未来开发计划算作已完成的产品功能。

对于确实受 iOS 6 内核限制而无法实现的能力，必须在正式兼容性清单中说明；不能假装已经实现。

## 1.3 系统兼容范围

| 项目 | 设计要求 |
|---|---|
| 最低系统 | iOS 6.0 |
| 主要系统 | iOS 6.0–6.1.6 |
| 扩展系统 | iOS 7+，以实际运行兼容性为准 |
| CPU | ARMv7 优先，ARMv7s 兼容 |
| 越狱 | 必需，Rootful |
| 屏幕 | 320 × 480pt 优先 |
| 最低内存目标 | 256 MB 设备 |
| 安装方式 | Cydia / dpkg / `.deb` |
| 网络依赖 | 无额外设备或远程控制核心 |

# 第二章：UI 与视觉系统

## 2.1 视觉定位

采用现代极简扁平化设计，不沿用 iOS 6 原生拟物风格。

核心视觉规范：

| 元素 | 规格 |
|---|---|
| 主品牌色 | `#A99AC8` |
| 交互强调色 | `#70558F` |
| 背景色 | `#F7F7F9` |
| 内容底色 | `#FFFFFF` |
| 主要文字 | `#25232A` |
| 导航栏 | 44pt |
| 底部导航 | 49pt |
| 内容边距 | 12–16pt |
| 列表行 | 48–56pt |
| 常规文字 | 13–15pt |
| 最小点击区域 | 44 × 44pt |

设计要求：

- 无拟物纹理和厚重渐变。
- 不使用实时毛玻璃、大面积模糊。
- 不采用复杂卡片层层嵌套。
- 优先使用原生 UIKit 控件与自定义轻量绘制。
- 长文字自动截断，不破坏列表布局。
- 动画短而简单，可在低性能设备上关闭。
- 状态颜色必须配合文字，不依赖颜色单独表达状态。

## 2.2 导航结构

底部采用四个固定标签：

**首页 / 代理 / 配置 / 日志**

设置通过首页右上角进入。

配置编辑器、配置检查、DNS 管理、网络诊断、连接详情和关于页面均为二级页面。

所有二级页面提供明确返回按钮，不强制用户依赖手势。

## 2.3 首页

首页必须包含：

**连接控制区**

显示代理开关和真实状态：

- 未连接
- 正在连接
- 已连接
- 正在恢复
- 部分降级
- 连接错误

点击连接按钮后，等待后台确认接管成功再显示已连接。

**当前代理区**

显示：

- 当前配置名称
- 当前策略组
- 当前实际节点
- 节点延迟
- 节点协议

点击节点可直接跳转至相应策略组的节点列表。

**模式切换区**

提供三个选项：

- Rule：按规则
- Global：全局代理
- Direct：直连

切换模式原则上不重启整个代理进程。

**流量统计区**

显示：

- 实时上传速率
- 实时下载速率
- 本次连接流量
- 连接时长
- 活动连接数

建议默认每两秒刷新一次 UI，具体由设备资源管理器调整。

**网络覆盖状态**

独立显示 TCP、UDP、IPv4、IPv6 与 DNS 接管状态。

不能仅凭代理进程运行就显示全部网络已被保护。

## 2.4 代理页面

采用两级布局：

**策略组列表 → 节点列表**

策略组页面展示：

- 策略组名称
- 类型
- 当前选择
- 当前实际出口
- 健康状态

节点列表展示：

- 节点名称
- 协议
- 最后测速延迟
- 当前选中状态

交互要求：

1. 点击节点直接请求切换。
2. 后台成功确认后更新勾选。
3. 切换失败则保留原选择。
4. 长按查看节点详情。
5. 支持单节点测速和批量测速。
6. 支持按原始顺序、延迟和名称排序。
7. 支持搜索与节点过滤。
8. 支持展示嵌套策略组和动态 Provider。
9. 未测速显示 `—`，超时显示对应状态，不使用 0ms 代表失败。

自动策略组需要显示实际出站节点，而不仅仅是策略组名称。

## 2.5 配置页面

提供完整的配置文件和订阅管理。

导入入口包括：

- URL 订阅
- 剪贴板
- Clash YAML 文件
- 节点 URI
- Base64 节点列表
- 二维码
- 本地文件

配置列表展示：

- 配置名称
- 订阅来源
- 最后更新时间
- 节点数量
- 配置状态
- 当前是否启用

配置详情提供：

- 手动更新
- 自动更新间隔
- 编辑名称和订阅地址
- 查看原始 YAML
- 本地覆盖项编辑
- 兼容性检查
- 导入与导出
- 删除和备份

更新订阅不能直接覆盖当前可用配置。

新配置需先解析、验证、准备，再应用。应用失败时继续使用原配置。

## 2.6 配置检查报告

沿用已经确认的 V2.1 设计。

问题分为三类：

**解析错误**

包括 YAML 语法、字段类型、参数范围、缺失字段及引用错误。

**功能不兼容**

包括协议缺失、系统接管能力不足、规则不支持及依赖缺失。

**运行警告**

包括资源压力、连接预检结果、DNS 风险与尚未确认的网络能力。

另设四级严重程度：

- 阻断
- 需要确认
- 提醒
- 未验证

页面布局采用：

**摘要 → 分类筛选 → 问题列表 → 详情 → 修复操作**

每个问题展示：

- 问题编号
- 所属类别
- 严重程度
- 配置字段
- 行列位置
- 错误原因
- 实际影响
- 修复建议

支持跳转编辑、复制错误、重新检查、查看修复前后变化。

解析器无法继续分析时，应显示后续项目未检查，而不是将其标记为通过。

## 2.7 日志与连接页面

日志页面顶部提供：

**日志 / 连接**

# 第三章：总体技术架构

## 3.1 核心结构

系统采用三个主要进程和一组核心模块。

### MuyuClash.app

负责全部 UIKit 页面、操作展示和用户交互。

不得直接操作特权防火墙和系统路由。

### muyu-supervisor

负责：

- 权限管理
- 后台进程启动与监控
- 网络接管规则安装
- 网络状态保存与恢复
- 系统异常处理
- 升级与卸载清理

### muyu-core

负责：

- 代理协议
- 连接转发
- DNS
- 规则引擎
- 策略组
- Provider
- 流量统计
- 连接日志

Core 可采用 C/C++ 与经过适配的其他语言组件组合实现。

协议优先静态集成，减少旧设备上的进程数量。

## 3.2 功能模块

| 模块 | 职责 |
|---|---|
| Config Engine | YAML、订阅、校验、配置快照 |
| Rule Engine | Clash 规则解析与匹配 |
| Policy Scheduler | 策略组、节点选择、测速 |
| DNS Engine | 普通 DNS、加密 DNS、Fake-IP |
| Proxy Registry | 协议注册与能力检测 |
| Transport Layer | TCP、UDP、TLS、QUIC 等 |
| Network Capture | TUN、PF、Socket 接管 |
| Connection Manager | 会话、流量、超时、关闭 |
| Runtime Manager | Core 生命周期与资源控制 |
| Diagnostics | 配置报告、运行错误与诊断 |

## 3.3 本地控制通信

UI、Core 和 Supervisor 通过有权限控制的本地 IPC 通信。

优先使用 Unix Domain Socket。

控制接口按以下命名空间组织：

| 接口 | 功能 |
|---|---|
| `service.*` | 启动、停止、状态 |
| `config.*` | 导入、检查、应用、回滚 |
| `proxy.*` | 节点和测速 |
| `group.*` | 策略组选择 |
| `provider.*` | 订阅更新 |
| `dns.*` | DNS 查询和缓存 |
| `rules.*` | 规则匹配 |
| `connections.*` | 连接与统计 |
| `network.*` | 接管与恢复 |
| `diagnostics.*` | 诊断与报告 |
| `system.*` | 设备与核心能力 |

IPC 消息必须有请求 ID、协议版本、错误码、超时和权限检查。

不默认开放公网控制接口。

# 第四章：网络接管系统

## 4.1 总体目标

让被接管的 iOS 网络流量进入统一的 MuyuClash 路由引擎。

流量处理流程：

应用网络流量 → Network Capture → Flow Engine → DNS/Rules → Policy Scheduler → Proxy Outbound → 网络出口

## 4.2 多后端架构

保留三个网络接管后端。

| 后端 | 用途 |
|---|---|
| TUN / utun | 优先研究的完整 IPv4/IPv6、TCP/UDP 接管方式 |
| PF + redsocks | 兼容性较明确的 IPv4 TCP 备选方案 |
| Socket Hook | 特殊应用或进程流量的补充接管 |

由 `CaptureCoordinator` 决定使用哪个后端。

不能默认同时开启多个可能互相冲突的后端。

不能在完整接管失败后静默降级为 TCP-only。

## 4.3 TCP 处理

TCP 引擎需要支持：

- 原始目的地址获取
- 域名关联
- 双向数据转发
- 半关闭
- 超时处理
- 流量背压
- 代理链
- 流量统计
- 断开与资源回收

## 4.4 UDP 处理

UDP 使用独立 Session Manager。

支持：

- 会话维护
- 目标地址关联
- 超时
- UDP DNS
- 普通应用 UDP
- QUIC 流量
- 数据报转发
- 资源清理

必须区别代理服务器的 UDP 传输能力与整机应用 UDP 的接管能力。

## 4.5 IPv6

IPv6 必须独立考虑 TCP、UDP、DNS 和路由。

如果当前网络后端无法安全接管 IPv6，则应明确显示覆盖限制，提供经过验证的保护或阻断方案。

不能简单通过关闭 AAAA DNS 应答宣称没有 IPv6 泄漏。

## 4.6 后端恢复

每次修改系统网络前，Supervisor 应保存必要的原始网络状态。

出现异常时，按照用户选择的保护模式恢复网络或维持阻断。

需要解决代理核心自身的连接再次被接管而造成循环的问题。

# 第五章：代理协议与传输

## 5.1 首次交付的协议目标

| 协议 | 目标范围 |
|---|---|
| HTTP / HTTPS | CONNECT、认证、代理入口与出站 |
| SOCKS5 | TCP、UDP |
| Shadowsocks | AEAD、2022 |
| VMess | AEAD、常见传输 |
| VLESS | TLS、Reality、Vision、UDP 编码 |
| Trojan | TLS、常用传输 |
| Hysteria2 | QUIC、认证、TCP/UDP |
| TUIC | v5、QUIC、TCP/UDP |
| WireGuard | 标准隧道能力 |
| AmneziaWG | 相应协议扩展 |
| AnyTLS | 现代 TLS 代理 |
| Snell | 适配基准支持的协议版本 |
| SSH | 代理出站 |
| ShadowsocksR | 旧协议兼容目标 |

协议是否能在 iOS 6 上启用，最终依据对应实现和系统能力；不可将未实现的协议显示为已支持。

## 5.2 共享传输层

传输组件包括：

- TCP
- UDP
- TLS 1.3
- WebSocket
- HTTP/2
- HTTP/3
- gRPC
- XHTTP
- HTTPUpgrade
- QUIC
- Mux
- 客户端 TLS Profile

每个协议通过统一 Adapter 调用传输层。

## 5.3 代理接口

协议模块提供：

- `validate`
- `create`
- `dial_stream`
- `open_datagram`
- `health_check`
- `capabilities`
- `metrics`
- `shutdown`

协议能力必须细分至传输组合。

例如，支持 VLESS TCP 不能自动代表支持 Reality + Vision。

## 5.4 实现与复用建议

优先研究 Senko 的 ARMv7 协议实现及旧版系统适配。

TLS 候选为 OpenSSL 或其他能安全适配 ARMv7 的现代 TLS 实现。

QUIC 候选为已有旧系统移植方案或 ngtcp2 相关组件。

WireGuard 可研究适合嵌入式环境的原生实现。

所有第三方代码必须先确认许可证、依赖和实际可分发条件，不能直接拼接互相冲突的代码。

# 第六章：Mihomo 配置兼容系统

## 6.1 兼容基准

以固定版本的 Mihomo 官方稳定实现作为行为标准。

正式编译前锁定其版本、Git 提交和配置文档，避免开发过程中不断改变兼容目标。

兼容性要求包括：

- 字段解释一致
- 默认值一致
- 规则匹配语义一致
- 策略组行为一致
- Provider 更新逻辑一致
- DNS 策略尽可能一致

不能仅以 YAML 能解析作为兼容成功的标准。

## 6.2 配置结构

目标兼容：

- `proxies`
- `proxy-groups`
- `proxy-providers`
- `rules`
- `rule-providers`
- `sub-rules`
- `dns`
- `sniffer`
- `tun`
- `listeners`
- `profile`
- `geox-url`
- `hosts`
- `ipv6`
- 其他基准内核支持的相关字段

其中 `tun` 需转换为旧版 iOS 实际可用的网络接管设置。

## 6.3 策略组

必须包含：

- select
- url-test
- fallback
- load-balance
- 嵌套策略组
- 动态 Provider
- 链式代理 / dialer-proxy
- 旧 relay 配置兼容处理

自动策略组按真实选路算法执行，不统一简化为选择最低延迟节点。

## 6.4 规则引擎

支持：

- DOMAIN / DOMAIN-SUFFIX / DOMAIN-KEYWORD
- DOMAIN-REGEX
- IP-CIDR / IP-CIDR6
- GEOIP / GEOSITE
- IP-ASN
- SRC-IP-CIDR
- SRC-PORT / DST-PORT
- NETWORK
- PROCESS-NAME / PROCESS-PATH
- RULE-SET
- AND / OR / NOT
- SUB-RULE
- MATCH

保留原始规则顺序。

采用 Hash、Trie、前缀树与预编译匹配器优化性能，但索引不能改变规则优先级。

## 6.5 Provider

支持远程、本地和内联 Provider。

应支持：

- 更新间隔
- 健康检查
- 节点过滤
- 名称处理
- 动态策略组引用
- 失败后使用缓存
- 原子更新

Provider 更新不能导致正在使用的配置突然失效。

# 第七章：DNS 引擎

## 7.1 核心能力

DNS Engine 需支持：

- 普通 UDP/TCP DNS
- DoH
- DoT
- DoQ（取决于 QUIC 实现）
- Redir-Host
- Fake-IP
- Hosts
- TTL 缓存
- 规则化 DNS 上游
- DNS fallback
- 代理节点域名解析
- 直连 DNS
- IPv6 AAAA 处理

## 7.2 解析逻辑

至少区分：

1. 应用 DNS 请求。
2. 代理服务器地址解析。
3. 直连出站的 DNS 请求。

避免节点解析进入自身代理而形成死循环。

Fake-IP 需要映射表和连接生命周期管理。

只有网络接管层能正确处理对应映射流量时，才可启用相应 Fake-IP 模式。

## 7.3 DNS 安全

需要保证：

- 不无提示回退至不符合用户策略的 DNS 上游。
- 解析失败时提供明确原因。
- 能够显示 DNS 来源和实际出口。
- 不能仅凭代理节点连接成功就认为没有 DNS 泄漏。

# 第八章：核心状态与热更新

## 8.1 代理生命周期

状态统一定义为：

`STOPPED → VALIDATING → PREPARING → STARTING → RUNNING`

额外状态：

- DEGRADED
- RECOVERING
- STOPPING
- FAILED

状态由后台服务维护，UI 只能显示真实状态。

## 8.2 配置热更新

每次成功应用配置时创建新的 `ConfigGeneration`。

新连接使用新配置。

现有连接原则上继续保留旧配置，直到自然结束或触发安全策略。

新配置失败时，立即放弃新 Generation，继续使用原有可用配置。

## 8.3 连接管理

每个连接记录：

- Connection ID
- 源与目标
- 网络协议
- 域名
- 规则命中
- 策略组
- 实际节点
- 配置版本
- 流量统计
- 状态与错误信息

不可靠的进程和域名元数据必须标记为未知，不能随意推断。

# 第九章：后台运行与故障恢复

## 9.1 常驻服务

使用越狱环境中的 launchd 管理后台组件。

关闭 App 界面不能结束代理服务。

Supervisor 监视 Core 状态，防止核心崩溃后系统网络规则失去管理。

## 9.2 自动恢复

需要处理：

- Core 异常退出
- DNS 模块失败
- 网络断开和重连
- Wi-Fi / 蜂窝接口切换
- 配置应用失败
- 代理服务器连接异常
- 设备重启

自动恢复应有退避和重试上限，不允许进入无限快速重启循环。

## 9.3 保护模式

提供：

**网络恢复优先**

核心失效时尽可能恢复正常网络，允许可能的直连，并明确告知用户。

**严格阻断**

核心失效时维持经过验证的网络阻断规则，防止未经代理的流量外泄。

严格阻断模式只在对应后端的保护机制确实可用时启用。

## 9.4 紧急恢复

必须有独立于主 Core 的网络恢复方式。

即便 UI 无法打开，也应能够通过系统包管理或独立恢复组件清理 MuyuClash 的接管状态。

# 第十章：性能与旧设备适配

## 10.1 性能目标

最低以 256 MB 内存设备为设计对象。

功能不能为了减少内存而静默删减，但内部应优先采用低开销实现。

## 10.2 优化措施

- UIKit 列表复用。
- 配置解析与网络 I/O 不阻塞主线程。
- 流量统计低频刷新。
- 限制并发测速数量。
- Geo 数据按需加载。
- Provider 共享缓存。
- 规则索引压缩。
- 连接对象及时回收。
- TLS/QUIC 缓冲限制。
- 日志采用有上限的环形缓存。
- 不使用持续动画和实时模糊。
- 资源紧张时减少非必要后台任务。

建议初始默认测速并发为 3，并允许资源管理器动态降低。

## 10.3 资源限制

资源管理器应限制：

- 活动测速数量
- 下载任务
- 日志内存
- DNS 缓存
- Fake-IP 映射数量
- 连接缓存
- QUIC 传输缓存

大型订阅或规则数据库应支持流式解析或紧凑存储，避免将多个完整副本同时保留在内存中。

# 第十一章：安全与隐私

需要实现：

- 节点密码和订阅令牌保护。
- 普通日志自动脱敏。
- 本地 IPC 权限校验。
- 配置文件访问权限限制。
- TLS 证书验证默认开启。
- 远程 Provider 路径限制。
- 不允许 YAML 导入任意执行系统命令。
- 限制恶意配置的嵌套与资源消耗。
- 不默认开放局域网控制接口。
- 不默认允许 LAN 代理连接。
- 卸载时清理网络接管状态。

配置订阅来自不可信来源，不得直接赋予其 Root 执行能力。

# 第十七章：技术风险与最终取舍

当前最难的部分仍是旧版 iOS 的完整网络接管，以及现代 TLS/QUIC 协议的移植。

需要特别注意：

1. iOS 6 没有现代 Packet Tunnel Provider 体系，必须依靠旧系统兼容的接管机制。
2. TUN/utun 在不同旧系统及越狱环境中的行为可能不同。
3. 256 MB 内存设备不适合直接照搬完整现代 Mihomo 运行时。
4. 部分现代协议组件需要调整编译器、TLS 后端或系统调用适配。
5. 第三方源码的许可证可能影响整个项目的发布许可证。

技术实现应尽量复用经过验证且许可证兼容的旧版 iOS 原生实现，避免不必要的重复开发。

如果最终使用 Senko 的 GPL 代码，需要履行相应 GPL 义务。不得直接把具有修改版分发限制的 vless-core-app 代码当作可自由发布的组件。
